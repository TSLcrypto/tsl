# Security policy

## Supported scope

Security reports may cover:

- the published TSL contract source in `contracts/TSL.sol`;
- discrepancies between this repository and the verified contract at `0xD12ECbD5f508106ec242881530767FF15A6A7549` on BNB Smart Chain;
- official token metadata, token lists, links, and identity references;
- repository automation or documentation that could misdirect users to an incorrect contract or destination.

Third-party wallets, exchanges, explorers, indexers, liquidity pools, websites, and social platforms are governed by their own security programs unless the issue is caused by information published in this repository.

## Reporting a vulnerability

Send a private report to [info@tslcrypto.com](mailto:info@tslcrypto.com) with:

- a clear description of the issue and expected impact;
- affected contract address, network, file, URL, or commit;
- reproduction steps or a minimal proof of concept;
- relevant transaction hashes, block numbers, or screenshots;
- suggested remediation, if known;
- a safe contact method for follow-up.

Do not open a public Issue or Pull Request for an unpatched active exploit. Never include private keys, seed phrases, API keys, access tokens, personal data, or funds in a report.

## Safe-harbor expectations

Research should avoid privacy violations, service disruption, social engineering, credential theft, denial of service, and movement of assets that are not owned by the researcher. Use test environments or minimal non-destructive demonstrations whenever possible.

Public disclosure should wait until the issue can be assessed and users can be protected. This policy does not promise a reward, bounty, or specific response time.
